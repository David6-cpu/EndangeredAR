## Scope recovery

The product research target was reduced from broad DialogueAct and
EmotionTone heads to one binary decision:

```text
GreetingEligibility = Greeting | NotGreeting
```

The question is whether the original user message and final assistant reply
together constitute a greeting interaction that might support a future Wave
candidate. Emotion classification remains historical R3.4A evidence and is
not a Wave product gate. No Emotion head was trained in this recovery.

The studied dual gate is:

```text
DeterministicGreetingIntent(userMessage)
AND LearnedGreetingClassifier(userMessage, assistantReply)
AND confidence >= devThreshold
AND margin >= devThreshold
```

This gate produces a research prediction only. It does not emit or execute an
animation candidate.

## Gold v2

Gold v2 contains 320 unique User/Reply pairs:

- 110 Greeting positives;
- 210 safety-critical hard negatives;
- 110 unique positive Pair inputs;
- 210 unique negative Pair inputs.

All rows are marked `agent_reviewed_pending_project_review`; therefore
`fullyHumanReviewed=false`. Gold v2 is excluded from vocabulary creation,
early stopping, threshold selection, temperature calibration, and model/input
selection. The experiment locks its candidate before reading Gold v2.

User-only and Reply-only projections repeat effective inputs because a fixed
message can pair with several replies. Their metrics are retained as research
evidence, but those input forms cannot satisfy the independent Gold size gate.

## Conditional deployment gates

The numerical Test gate passes, the numerical Gold v2 gate passes, and Pair
input adequacy passes. The complete product quality gate remains false because
Gold v2 has not been independently reviewed by a user or project member.

Following the prescribed ordering, this recovery therefore did not perform:

- a new ONNX export or ONNX SHA/parity check;
- Unity Inference Engine import or CPU execution of the new model;
- signed iPhone install or fully offline inference;
- a 1,000-inference device stability loop;
- iPhone latency, incremental memory, or thermal measurement;
- Qwen, Idle, rotate, or zoom coexistence validation for this model.

The original R3.4A TextCNN Pair compatibility run remains historical technical
evidence. It cannot validate this new binary checkpoint. Preferred deployment
remains Unity Inference Engine 2.4.1 on CPU, conditional on all remaining
quality and device gates.

## Runtime safety boundary

A future product design may consider only:

```text
answerMode = social_chat
ContentAuthority = None
deterministic greeting intent = true
learned GreetingEligible = true
confidence and margin pass
no existing Eat or Taunt candidate
Wave capability, validator, and controller support all pass
```

The classifier must remain fail-closed and cannot directly emit a Wave,
Animator trigger, `AIAction`, state name, Unity method, Memory/Progress write,
or business command. R3.4A.1 does not integrate this policy.

## Reproducibility

- Tokenization: fixed Unicode character IDs; PAD 0, UNK 1, USER 2,
  ASSISTANT 3, SEP 4.
- Padding: right; Pair truncation preserves the reply and then the user tail.
- Linear: character TF-IDF 1-4 grams, balanced Logistic Regression.
- TextCNN: embedding 32, kernels 2/3/4, 32 channels each, dropout 0.2.
- Training: AdamW, learning rate 0.001, batch 128, 20 maximum epochs,
  patience 4, inverse-square-root class weights.
- Threshold and temperature selection: Dev only.
- Test: evaluated after policy lock.
- Gold v2: loaded after candidate lock for final diagnostics only.

## Exit decision

R3.4A.1 recovered the technical and numerical Greeting classifier result, but
it has not recovered the full acceptance chain. The next allowed work is an
independent project-member review of Gold v2, followed by a rerun if any labels
change. Only a still-passing reviewed result may authorize ONNX parity, Unity
CPU inference, and signed fully offline iPhone validation.

Do not begin R3.4B or R3.4C from the current result. No Wave asset work is
authorized.
