## Scope

R3.2A restructures the existing one-action vertical slice into a typed,
capability-aware foundation. It does not add a second product action. The only
runtime action values remain `AIAction.None` and `AIAction.Taunt`.

This phase does not add Eat, Happy, Sad, Curious, emotion suggestions, task
context, action queues, interruption, new animation clips, Animator states,
animals, prompt behavior, grounding topics, or R2 knowledge-schema changes.

## Character capability contract

`CharacterCapabilityProfile` is an animal-owned `ScriptableObject` containing
a typed allowlist of executable `AIAction` values. The Sensen profile contains
only `Taunt`; `None`, invalid enum values, and duplicate entries are filtered.
`AnimalDefinition` carries an optional capability profile, and the canonical
animal asset builder creates and assigns `SensenCapabilities.asset`.

The current model loader exposes the capability profile belonging to the
currently loaded animal. It does not globally discover controllers or retain a
capability from a replaced model.

## Candidate selection policy

`AIActionCandidate` separates an untrusted candidate from validated execution.
Its source is currently limited to deterministic original-user intent. The
policy emits zero or one action:

- duplicate identical candidates collapse to one action;
- conflicting, malformed, unsupported-source, invalid-action, or wrong-animal
  candidates collapse to `None`;
- provider suggestions must exactly agree with deterministic intent from the
  original user message;
- provider prose cannot grant an action.

All Local, Cloud, server-rule, server-knowledge, and Unity-knowledge completion
paths pass through this policy before validation.

## Capability and runtime validation

`AIInteractionValidator` accepts a selected action only when the existing R3.1
request, animal, page, active-model, and generation guards pass and both of
these capability checks agree:

1. the current animal capability profile supports the typed action;
2. the current active model controller supports the same typed action.

The validated result remains a one-use `ValidatedAIAction`. It cannot accept a
state name, Animator parameter, or method name. Missing profiles, denied
capabilities, unsupported controllers, fallback models, stale requests, wrong
animals, inactive pages, and busy controllers suppress animation without
losing or duplicating the chat answer.

## Generalized animation controller

`AnimalModelController` now provides the fixed typed API:

- `SupportsAction(AIAction)`
- `CanRequestAction(AIAction)`
- `TryPlayAction(AIAction)`
- `CurrentAction`
- `IsBusy`

Only the explicit `Taunt` switch branch maps to the reviewed Animator trigger,
state, and timeout. No dynamic string-to-state or string-to-parameter mapping
exists. The existing `TryPlayTaunt()` method remains a thin compatibility
wrapper. Same-frame duplicate requests, transitions, and active playback remain
busy; the controller clears the pending action only after the reviewed Taunt
lifecycle returns to Idle or a bounded entry timeout safely expires.

## Security and product-state boundaries

- `.env.local`, `.local-models`, and GGUF weights remain outside Git.
- Cloud credentials remain server-side and are absent from Unity assets.
- No provider or user text can name arbitrary Animator states, parameters, or
  runtime methods.
- Action history is not persisted, and history restoration cannot replay an
  action.
- Actions cannot modify missions, progress, badges, rewards, unlocks, knowledge
  citations, or chat-history schema.
- No animation, Animator Controller, model, prompt, knowledge, task, or Python
  product asset changed in this phase.

## Decision

R3.2A Multi-Action Capability Foundation is **accepted**. The project now has a
typed animal capability profile, deterministic zero-or-one candidate policy,
capability/controller intersection, and generalized fixed-action controller
without expanding behavior beyond the already accepted Taunt action.

R3.2B has not started. A second action must not be enabled until its product
purpose, licensed animation asset, capability entry, deterministic intent
contract, validation policy, tests, and physical-device acceptance are reviewed
as a separate phase.
