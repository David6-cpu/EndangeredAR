# R3.3C AI Route Provenance and Intent Defect Gate

Date: 2026-08-26

## Status

The provenance and intent defect gate has execution-level evidence for Local, Cloud, deterministic Memory, and Unity fallback routes. The R3.3C final A-H acceptance remains paused and is not covered by this record.

## Scope

This gate adds Development-only reply provenance, verifies that model routes perform real completions, and closes two intent classification defects. It does not change Character Memory storage, Progress, canonical facts, or action permissions.

## Observed Replies

### Open social chat

For `我今天心情一般般`, the original device run finished as `unity_fallback`, not as an LLM completion. The attempted Cloud route failed and the fixed social reply came from the Unity fallback service.

### Animal friends

Before the fix, `你有什么动物朋友` had `MemoryMentionPolicy=None` but the knowledge retriever incorrectly matched the identity fact through the phrase `什么动物`. The resulting identity answer and citations were a false-positive grounding result. A shared Python/Unity vector now keeps animal-friend questions in `social_chat` with no grounded fact while preserving valid identity and scientific-name questions.

### Explicit recall

Before the fix, `你还记得我做过什么吗` was classified as `None`, while the variant containing `以前` was classified as `ExplicitRecall`. Both variants now resolve through the deterministic Memory path. The observed empty-memory response reported `memory_deterministic`, `memory_recall`, and `explicit_recall` without invoking a Provider.

## Defects Closed

### Coroutine forwarding

Forwarding overloads in `ChatApiClient` yielded a nested enumerator instead of returning it. `CloudLLMProvider` correctly rejected the opaque yield, so the HTTP request never ran. The forwarding overloads now return the real request enumerator, and focused tests traverse the production overload chain.

### Development LAN HTTP policy

Unity Player settings rejected the development device's local HTTP request before transport. The project now permits insecure HTTP only for Development Builds. Non-Development Players remain blocked.

### Safe transport diagnostics

Cloud and Local failures now expose bounded reason codes rather than URLs, response bodies, prompts, or raw exception text. The Development-only panel shows final source, answer mode, route mode, provider attempts, grounding topic, Memory policy/status, fallback state/reason, and elapsed time.

## Isolation

- The provenance UI is compiled only for Editor or Development Builds.
- The panel does not display prompts, user message text, API credentials, Memory JSON, filesystem paths, network addresses, or device identifiers.
- Memory deterministic replies remain separate from Local, Cloud, server rule, server knowledge, and Unity fallback results.
- Provenance metadata does not grant grounding, Memory recall, or action authority.
