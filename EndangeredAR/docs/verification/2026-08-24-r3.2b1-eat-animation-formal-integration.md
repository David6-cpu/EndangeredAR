## Import and Avatar contract

The independent animation FBX uses Generic animation and `Copy From Other
Avatar` with the valid Avatar embedded in the formal
`sensen_rigged_100k.fbx`. The imported clip is named `Sensen_Eat`; root
rotation, root position Y, and root position XZ are baked into pose. Cameras,
lights, extra materials, and Animation Events are not imported. The formal
100k mesh, skeleton, material, Idle, and Taunt assets remain unchanged.

## Animator and controller

`SensenRigged.controller` now has fixed `Taunt` and `Eat` Trigger parameters.
Idle remains the default state. The only action transitions are:

- `Idle -> Taunt -> Idle`
- `Idle -> Eat -> Idle`

Both action states return through Exit Time. There is no Any State transition,
action-to-action transition, queue, interruption path, or root motion.

`AnimalModelController` maps `AIAction.Eat` to a reviewed, fixed action spec:
the Eat Trigger hash, Eat state hash, `Sensen_Eat` clip name, bounded entry
timeout, and bounded safety timeout. It reuses the existing pending/busy
lifecycle. Same-frame duplicates, transitions, Taunt-during-Eat, and
Eat-during-Taunt fail closed as Busy and are never queued.

## Capability and reproducibility

Sensen's `CharacterCapabilityProfile` contains exactly `Taunt` and `Eat`.
Missing profiles and unsupported animals/controllers still fail closed.
`AnimalContentAssetBuilder` and `SensenRiggedAssetBuilder` regenerate the same
capability, importer, Animator parameter/state/transition, and prefab contract
without duplicates or loss of Taunt. A second Builder run and the focused
idempotence suite passed.

## AI isolation

Eat is an internal character capability only in this phase. The strict
transport parser continues to accept only exact lowercase `taunt`:

- `eat` -> `AIAction.None`
- `Eat` -> `AIAction.None`
- `EAT` -> `AIAction.None`

Local and Cloud providers use that same parser. Python intent logic still
exposes only None/Taunt. Server rule, Unity knowledge, grounded diet answers,
history restoration, prompt injection, and task state cannot create Eat. A
grounded answer to `森森，你平时吃什么？` still returns canonical facts and
citations without animation.

## Development and Release isolation

The existing `AnimalAnimationDebugPanel` adds one fixed `PLAY EAT` button next
to the accepted `PLAY TAUNT` control. It resolves the current active model for
each request and calls the typed controller directly. It does not create an
`ActionCandidate`, access AI providers, write chat history, or mutate missions,
progress, badges, rewards, or unlocks.

Both Development classes remain wrapped by
`#if UNITY_EDITOR || DEVELOPMENT_BUILD`. A non-Development macOS smoke build
succeeded. Its runtime assembly and scene data contain no Development panel,
bootstrap, `PLAY EAT`, or `ANIMATION DEV` symbols, and no Missing Script was
reported.

was incorrectly sent through the intentional legacy GLB baseline path. A

fixed so both Rigged and Eat modes use the normal scanner-driven Rigged path;
Legacy mode alone forces GLB fallback.
