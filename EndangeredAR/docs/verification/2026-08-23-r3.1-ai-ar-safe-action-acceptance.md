## Scope

R3.1 adds one deliberately narrow AI-to-AR action: an explicit user request can
play Sensen's existing Taunt animation after the answer is accepted by the
normal chat completion path. It does not add arbitrary Animator access, model-
generated method names, emotion control, task context, rewards, progress,
unlocks, new animations, or a second animal action.

## Action contract

The only public action values are `None` and `Taunt`. Python and C# use the
same versioned fixture, `content/quality/sensen-action-intent-vectors.json`, to
classify a small allowlist of explicit original-user intents. Provider prose is
not trusted to grant an action.

The wire field is `actionSuggestion`. Unity parses only the exact lower-case
value `taunt`; missing, malformed, differently cased, unknown, or injected
values become `None`. The server, Local LLM, Cloud LLM, server-rule response,
and Unity local-knowledge fallback all apply the same deterministic resolver.
Grounded scientific questions and prompt-injection cases cannot receive Taunt
metadata.

## Validation and execution boundary

`AIInteractionValidator` accepts Taunt only when all of these remain true at
completion time:

- the original user message independently resolves to Taunt;
- `ChatRequestState.CanComplete` accepts the request ticket and current animal;
- the response animal matches the current animal;
- the current animal is `sensen`;
- the interaction page is still active;
- the loader owns the exact current active model and controller;
- the controller supports the current animal and is not busy.

Validation does not execute the action or consume the chat request. A successful
validation creates a one-use `ValidatedAIAction`. The existing completion flow
then consumes the request ticket, updates the answer bubble, writes user and AI
history once, restores the input state, and only then consumes the one-use
action token. Action failure is logged but cannot replace the answer, duplicate
history, retry the provider, or queue another animation.

Stale, switched-animal, inactive-page, missing-model, fallback-model, and busy
results therefore preserve normal chat behavior while suppressing the action.
Chat history remains the existing `role` and `content` schema, so restoring old
or new history never replays Taunt.

## Security and product-state boundaries

- Cloud credentials remain server-side and are absent from Unity and Git.
- `.env.local`, `.local-models`, and GGUF model weights remain untracked.
- Arbitrary action names, Animator parameters, state names, and method names are
  not accepted from providers or users.
- Knowledge text and model prose cannot directly invoke Unity methods.
- Taunt cannot modify missions, progress, badges, rewards, unlocks, or chat
  history schema.
- R3.1 does not implement `actionSuggestion` for a second action, emotion
  suggestions, task context, streaming, or native mobile inference.

## Decision

R3.1 AI-to-AR Safe Action MVP is **accepted** for the single Taunt vertical
slice. Local, Cloud, rule, and Unity-knowledge response paths preserve one
typed action contract; Unity independently revalidates original intent and
current interaction state before one-shot execution. Stale and busy actions are
suppressed without losing or duplicating the chat answer.

No second action should be added automatically. A later phase may evaluate one
additional fixed action only after it has a reviewed animation asset, explicit
intent fixture, product rationale, validator policy, device acceptance, and the
same no-side-effect guarantees. R3.2 and broader AI animation control have not
started.
