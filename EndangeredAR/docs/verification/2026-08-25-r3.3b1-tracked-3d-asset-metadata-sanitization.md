# R3.3B.1 Tracked 3D Asset Metadata Sanitization

Date: 2026-08-25

Branch: `codex/r3.3b-fbx-path-sanitization`

Status: accepted. Automated acceptance, physical-device installation, stable
process launch, and final visual smoke all passed.

## Scope

This maintenance stage removes local source-path metadata from three tracked 3D
assets without rewriting Git history or changing product behavior. It does not
change the character mesh, rig, skinning, animations, material assignment,
Animator, Prefab, canonical knowledge, Progress, Memory, AI routing, grounding,
actions, Scene, or ProjectSettings.

The current tracked tree is scanned as both text and binary data. Synthetic
negative-test paths are constructed at runtime instead of being stored as
contiguous local paths in source files. No scanner allowlist was added for the
three product assets.

## Toolchain contract

FBX sanitization uses Blender 5.2.0 LTS arm64 and its built-in
`io_scene_fbx.parse_fbx` and `io_scene_fbx.encode_bin` modules. The tool refuses
unknown runtime versions or internal API contracts.

## Equivalence evidence

Each FBX was parsed before and after sanitization. Element hierarchy, property
order and types, scalar values, decoded numeric arrays, object IDs, Connections,
Models, Geometry, Deformers, Materials, Texture/Video associations, animation
stacks/layers/curve nodes/curves, Pose, and GlobalSettings were compared. The
only normalized writer fields allowed were root FileId, root CreationTime,
footer/padding, and compressed byte representation where decoded arrays were
identical. No non-target semantic differences were found.

Blender import-level comparison against the previous formal assets also passed:

- Rigged mesh, UVs, normals, tangents, skin weights, material slot, bone names,
  parent hierarchy, rest matrices, object hierarchy, Idle, Taunt, curve paths,
  keyframe times, and keyframe values were identical.
- Eat bone hierarchy, object hierarchy, action paths, curve indices, keyframe
  times, and keyframe values were identical.

A detached Unity worktree with a fresh Library imported all three candidates
before formal replacement. The focused Rigged asset fixture passed 15/15,
EditMode passed 332/332, and PlayMode passed 33/33. The formal worktree then
passed the same 15/15 focused fixture, Python 102/102, EditMode 332/332, and
PlayMode 33/33.

Real Unity Game View acceptance passed for both Idle/Eat/Idle and
Idle/Taunt/Idle. The imported model remained 54,684 Unity vertices, 100,000
triangles, and 33 bones. Host and root transforms remained stable, and the
legacy GLB fallback stayed hidden while the rigged character was active.

The sanitized product tree was also exported as an iOS Development build,
signed with the existing local workflow, installed on the physical test device,
and launched normally. The process remained stable with no UIScene assertion,
SIGTRAP, fatal exception, or crash in the inspected launch log. Final manual
visual smoke confirmed a non-black screen, visible Sensen character, and normal
Idle animation. Device identifiers and signing details are intentionally not
recorded.

## Non-goals

This stage does not remove historical bytes from old public commits and does
not use force push or history rewriting. It only makes the current branch and
eventual current main file trees path-clean. It does not start R3.3C.
