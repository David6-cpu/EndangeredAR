# R3.3C0 iPhone On-Device LLM Spike Acceptance

Date: 2026-08-27

## Status

R3.3C0 Spike passed. The installed Development iOS app loaded the approved Qwen2.5-1.5B-Instruct GGUF and produced a real llama.cpp completion on the iPhone while Mac inference services, iPhone Wi-Fi, and iPhone cellular data were off.

This result proves the native inference foundation only. The regular chat input is intentionally not connected to the on-device provider in this Spike. Production prompt construction, local R2 composition, Current Context, Character Memory, response validation, and the final action-enabled chat route remain a later migration stage. R3.3C final A-H acceptance remains paused.

The official `ios-device` XCFramework build completed from the pinned source commit. The generated iOS app then completed an `arm64` Debug build and passed strict code-signature verification.

The embedded llama binary targets iOS 16.4 and links only Apple Foundation, Metal, Accelerate, CoreFoundation, Objective-C, C++, and system libraries. No Mac dynamic library is required.

## Isolation Boundary

The Development-only Spike panel uses the native backend directly and accepts only the fixed prompt. It does not reference `AIManager`, R2 knowledge retrieval, R3.3A Current Context, R3.3B Character Memory, Progress, actions, Cloud, or the Mac HTTP provider.

Consequently, the normal chat input does not yet use the iPhone model. With networking and Mac services off, that older chat route cannot provide a completion. This is expected at the Spike boundary and is the next production migration task, not evidence of a failed native completion.

The current Mac Python and llama.cpp route remains Development-only benchmark infrastructure. It must not be described as iPhone-local inference.

## Exit Decision

R3.3C0 has proved real iPhone on-device Qwen inference without Mac, LAN, or Cloud availability. The next stage may connect a production `OnDeviceLLMProvider` to Unity-owned prompt construction and local authority data.

R3.3C final A-H must not resume until the regular chat route no longer depends on Python or HTTP and normal provenance reports `languageGenerator=on_device_llm` and `finalSource=on_device_llm`.
