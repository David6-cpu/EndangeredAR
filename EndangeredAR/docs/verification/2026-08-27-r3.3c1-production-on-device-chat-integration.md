**Date:** 2026-08-27

**Branch:** `codex/r3.3c-memory-aware-dialogue`

**Scope:** Connect the real bottom Chat UI to iPhone on-device Qwen while preserving Unity-owned facts, state, Memory, citations, and action authorization.

**Result:** Core R3.3C1 gate passed. Full R3.3C A-H remains a separate pending acceptance stage.

## Stage Boundary

- R3.3C0 proved that the pinned llama.cpp runtime and approved Qwen GGUF can generate text on iPhone.
- R3.3C1 connects the production Chat UI to that runtime and removes Python, HTTP, Mac, LAN, Cloud, server replies, and Unity fixed-chat fallback from the production conversation path.
- Python, the Mac llama.cpp server, and Cloud providers remain development, reference, benchmark, and regression tools only.
- This stage does not change Progress writes, Memory event storage, canonical facts, capability profiles, Animator state, or action permissions.

## Crash Gate

The first production Chat UI device run reproduced a native abort when a prompt larger than the 256-token logical batch reached `llama_decode`. The prompt budget allowed a larger valid request, so the runtime contract was internally inconsistent.

The fix:

1. Raises the logical batch to the full accepted prompt budget while retaining a 256-token micro-batch.
2. Adds a pre-decode native guard that returns `prompt_batch_exceeded` instead of calling llama.cpp with an invalid batch.
3. Maps the new native error through the managed sanitized error contract.
4. Adds contract tests for both the runtime profile and pre-decode guard ordering.

The original message `我今天心情一般般` was then repeated successfully on the physical device without another crash.
