## Memory-positive Reunion Defect And Fix

The first clean-container A attempt exposed a validation blocker: the generated
Reunion wording made an unsupported recency claim, so the response correctly
failed validation. CharacterMemory strict repair was still nondeterministic and
did not provide an exact trusted repair turn.

RED coverage proved that the Memory-positive repair lifecycle lacked a bounded
exact reply. The minimal fix made CharacterMemory repair deterministic, replaced
the repair user turn with an exact-copy request, and supplied a trusted bounded
Reunion / ExplicitRecall repair while preserving the on-device provider and the
existing generation budget. The focused test passed, all suites were rerun, the
iOS app was rebuilt over the same isolated container, and A and B then passed
against the preserved genuine `D1 M1 K1 B1` state.

Fix commit: `effd0af60f952c6866f5745e780231ede10326ae`.
