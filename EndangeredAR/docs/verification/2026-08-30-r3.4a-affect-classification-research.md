## Dataset and rights decision

| Dataset | Research decision | Rights and product conclusion |
| --- | --- | --- |
| CPED | Adopted for local-only research | Official repository and paper were pinned. It supplies short Chinese multi-turn text, emotion, and dialogue-act labels, but the utterances derive from 40 television shows. The repository license is not treated as clearance for commercial redistribution of the dialogue or derived public weights. |
| Ren-CECps | Rejected | Emotion-only long-form blog material, separate author agreement required, no agreement obtained. |
| NLPCC 2013/2014 emotion corpora | Rejected | Emotion-only social posts, unclear current commercial/redistribution grant, and higher privacy/copyright risk. |
| Kaggle mirrors | Not used | A public mirror is not evidence of commercial, redistribution, or derived-weight rights. |

## Final project taxonomy

DialogueAct:

`Neutral`, `Greeting`, `Comfort`, `Appreciation`, `Question`, `Other`

EmotionTone:

`Neutral`, `Joy`, `Warm`, `Sadness`, `Worry`, `Anger`, `Surprise`, `Other`

`Encouragement` was removed because CPED has no dependable source label and the
Gold set cannot be reused as training data. Rare CPED acts and emotions were
merged into bounded project labels instead of preserving a large, sparse
taxonomy. The complete deterministic mapping is versioned as
`r3.4a-taxonomy-v1`.

## Gold set and privacy

The 72-row Gold set contains only project-authored, reviewed, non-private
User/Reply pairs. It covers Greeting, Comfort, Joy, Appreciation, neutral
science, negation, technical text, history questions, and prompt-injection
false positives. Dialogue distribution is 30 Neutral, 12 Greeting, 9 Comfort,
8 Question, 7 Other, and 6 Appreciation.

It contains no real user chat, Character Memory, Progress, device log, cloud
log, identity, nickname, email, device information, or production free text.
Automated checks reject a non-project source, duplicate/contaminating rows, and
training access to Gold.

## Input-form experiment

- **A - Reply-only:** trained and evaluated for all three architectures.
- **B - User + Reply Pair:** trained and evaluated on the same splits for all
  three architectures.
- **C - Pair + controlled metadata:** not trained. CPED has no project-owned
  variation of `answerMode` or `ContentAuthority`; constants or synthetic
  values would not establish benefit.

Pair input improved raw Greeting precision and/or recall for every architecture
but did not improve aggregate Macro-F1. The recommendation for a future
rights-cleared, Greeting-focused dataset is Pair, without metadata until a new
owned experiment proves a gain.

## Deployment recommendation

If a later rights-cleared model meets quality and device gates, the preferred
path is Unity Inference Engine + ONNX, TextCNN Pair, CPU backend. It keeps one
cross-platform C# policy surface and avoids a second iOS-only business bridge.
Core ML remains an untested fallback if Unity Player compatibility fails.
Asking Qwen to emit labels is rejected for this independent classifier goal.

A future `ResponseAffectClassifier` may accept only the original user message,
the final validated assistant reply, `answerMode`, and `ContentAuthority`, and
return typed labels, confidence, margin, and model version. First use remains
restricted to `social_chat` plus `ContentAuthority=None`. It must not receive
Memory events, citation URLs, prompts, identity, internal IDs, or device data.

No classifier may output an Animator trigger, state, `AIAction`, Unity method,
object path, Memory write, Progress write, or business command. A later
application-owned candidate would still pass Action Policy, Character
Capability, `AIInteractionValidator`, and `AnimalModelController`; an existing
Eat/Taunt authorization would suppress any expression candidate.

## Exit decision

R3.4A demonstrates that a sub-megabyte dual-head TextCNN can run accurately at
the logit level and very quickly in Unity Editor. It does not demonstrate
product-worthy classification accuracy or a signed offline iPhone Player.

Do not begin R3.4B or R3.4C from this result. The next R3.4A gate is a distinct
development profile plus a fixed-text offline device run. Even after that,
product work requires rights-cleared Greeting-focused training data and a new
precision-first evaluation whose Test and Gold results materially exceed this
candidate.

## R3.4A.1-A.3 addendum (2026-09-01)

The preceding report remains the historical first-spike result. Subsequent
work narrowed the product question to binary Greeting eligibility, created a
rights-cleared project-authored recovery corpus, compared User-only,
Reply-only, and Pair inputs, and Dev-locked a TextCNN Pair candidate. Gold v2
then completed a blind 320/320 project-member review without entering training,
vocabulary, model selection, calibration, rule design, or threshold selection.

The locked candidate passed Test at precision 1.0000 and recall 0.7889, and
human-reviewed Gold v2 at precision 1.0000 and recall 0.9909, with zero
safety-critical false positives. ONNX export, PyTorch/ORT parity, and Unity
Inference Engine 2.4.1 CPU parity also passed.

R3.4A.3 subsequently closed most of the signed-device gap. The independent
full App signed, installed, launched, and ran fully offline on iPhone. Eight
fixed fixtures, 11 Product Scope cases, 1,000/1,000 CPU inferences,
dispose/reload, low-memory reload, runtime parity, and full-App Qwen/AR
coexistence passed. Mean/P95 latency was 0.1761/0.2947 ms, peak resident memory
rose 3,506,176 bytes above the initial sample, and thermal state remained fair.

The final acceptance gate still failed. For a real final validated Qwen reply
to the direct greeting fixture, deterministic intent and product scope were
true, but the locked TextCNN predicted `NotGreeting` with confidence 0.7338
and margin 0.4676. The required science Qwen pair was not recorded by the
exact Development fixture matcher, so only 2/3 Qwen pairs were stored. No
model, rule, temperature, confidence threshold, or margin threshold was
changed after observing this evidence.

The authoritative signed-device record is
[`2026-08-31-r3.4a3-signed-iphone-classifier-acceptance.md`](2026-08-31-r3.4a3-signed-iphone-classifier-acceptance.md).
R3.4A remains not fully accepted, and R3.4B remains closed.

## R3.4A.4-A.5 final decision addendum (2026-09-01)

The preceding status is retained as historical A.3 evidence. R3.4A.4 then
reproduced the TextCNN Pair response-domain miss against production-semantics
Qwen output. Rule-only reached precision 1.0000, recall 0.8667, and zero
safety-critical false positives in the Pilot; no learned User-only, Reply-only,
Pair, or reply-guard strategy provided a stable gain. Full Qwen-domain
retraining and Gold v3 were therefore not authorized.

R3.4A.5 froze `r3.4a5-greeting-intent-v1` and
`r3.4a5-greeting-scope-v1` before creating an independent user-only Gold set.
The project owner blind-reviewed 150/150 rows. The final 52 Greeting and 98
NotGreeting decisions differed from the design labels on two rows, contained
no unresolved decisions, and were not used to change either policy.

The frozen rule achieved precision 1.0000, recall 0.9423, F0.5 0.9879, zero
false positives, and zero safety-critical false positives. All 15 locked
ProductScope rejection vectors passed, including authoritative answers,
Memory/Progress, lifecycle failures, existing Eat/Taunt actions, mixed
requests, and prompt injection.

The final model-selection decision is:

- R3.4A research completed and accepted;
- learned affect/Greeting classification is technically feasible but remains
  research-only;
- learned classification is not selected for the first Wave product path;
- Wave v1 selects `DeterministicGreetingIntent + ProductScopeGate`;
- R3.4B is open for a separate Wave asset stage, but no Wave work begins here.

The authoritative final record is
[`2026-09-01-r3.4a5-deterministic-greeting-gate.md`](2026-09-01-r3.4a5-deterministic-greeting-gate.md).
