# R3.2B0 Sensen Eat Animation Asset Spike

Date: 2026-08-23

Status: technically validated and visually accepted. `Expressive` was selected
for R3.2B1 formal integration; `Subtle` remains repository-external.

## Scope

This spike created two repository-external Eat animation candidates on the
formal Sensen Generic rig. It did not modify AIAction, capability policy,
grounding, the Animator Controller, the rigged prefab, scenes, or product code.

## Source rig

- Formal source: `EndangeredAR/Assets/Art/Characters/Sensen/Rigged/Models/sensen_rigged_100k.fbx`
- SHA-256: `c885fe83a6605e71b2d977e28871f6259647754f79861320fbf68dec0b960926`
- Armature: `Armature`
- Root bone: `mixamorig:Hips`
- Bones: 33
- Existing clips: `Sensen_Idle` (91 frames), `Sensen_Taunt` (86 frames)
- Frame rate: 30 FPS
- Imported armature transform: rotation X 90 degrees, uniform scale 0.01
- Tail bones: absent, accepted non-blocking limitation

The Eat candidates retain the same names, hierarchy, armature transform,
coordinate conversion, and Generic Avatar relationship as the formal model.

## Tooling

- Blender: 5.2.0 LTS arm64
- Plugins: none
- Generator: `tools/art/r32b_build_eat_animation.py`
- Repository-external output root: a local-only art workspace retained outside
  the repository and not committed.

The script samples frame 1 of the formal Idle clip, authors fixed quaternion
keyframes on the existing bones, fixes the Hips pose at every key frame, returns
all bones exactly to the starting pose, and exports animation-only FBXs. The
formal `world` empty is retained during export so Unity keeps the binding prefix
`Armature/mixamorig:Hips/...`.

## Motion design

Both candidates are 106 frames / 3.5 seconds at 30 FPS and are non-looping:

1. Idle start
2. Eating hand lowers toward the torso
3. Hand returns to the mouth
4. Head and upper torso add a small chew response
5. A second hand-to-mouth beat
6. Hand lowers
7. Exact return to Idle pose

No prop, facial system, root movement, Animation Event, script, plugin, custom
shader, or new bone is included.

The first standalone export intentionally exposed a hierarchy issue: excluding
the formal `world` empty caused Unity to collapse the `Armature` path and report
33 missing transforms. Retaining the same root hierarchy fixed this to 0 without
changing the skeleton. Therefore the preferred integration is an independent
animation FBX sharing the formal Generic Avatar (scheme A). A regenerated
single-FBX model is not currently necessary.

The final one-hand pass avoids the earlier two-hand face occlusion. Current
renders show no visible skin tear, root drift, shoulder inversion, elbow snap,
head flip, or hand/body penetration at the authored key poses. The pointed hand
silhouette comes from the accepted character mesh and is present outside this
animation as well.

## Selection and handoff

The project owner selected `Expressive` for the competition/demo product because
its hand travel reads more clearly as eating at the current AR display scale.
`Subtle` remains a valid lower-amplitude fallback outside the repository.

The selected binary is identified by the complete SHA-256:

`66c6d474f3ac2053732a9af23b53e0d67621ee8b74dac9a4e062de15d48ffdcb`

R3.2B1 may therefore integrate only this Expressive animation into product
Assets. This approval does not authorize AI, grounding, provider, prompt, or
task-driven Eat behavior.
