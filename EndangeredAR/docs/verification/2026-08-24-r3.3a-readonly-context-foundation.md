# R3.3A Read-only Context Foundation Acceptance

Date: 2026-08-24

Branch: `codex/r3.3a-readonly-context`

Baseline: `62959dfc5b5269071eca6281fa2b1265627eecb6`

Status: accepted at the automated engineering gate. R3.3A adds a bounded,
read-only business-state snapshot to AI requests without adding persistent
memory, events, user accounts, or any AI-owned write path.

## Scope

The implemented path is:

`persisted progress + canonical animal/mission definition`
`-> IReadOnlyCharacterContextProvider`
`-> immutable value-only request DTO`
`-> AIManager request snapshot`
`-> Local / Cloud / Unity-knowledge routes`

The context is input data only. It cannot complete a mission, grant a badge,
change unlock state, alter an action capability, invoke an animation, or write
the progress repository.

R3.3A does not create a memory file, event store, memory summarizer, nickname,
user ID, level, score, relationship value, emotion value, task automation, or
long-term interaction memory. R3.3B and R3.3C have not started.

## Audited state sources

The persisted `AnimalProgressRecord` currently contains:

- `animalId`
- `unlocked` and `unlockedAtUtc`
- `learnedKnowledgeIds`
- `missionCompleted`
- `earnedBadgeIds`
- bounded recent conversation records (`role` / `content`)

The read-only context deliberately uses only the stable progress facts needed
by this phase: unlock state, distinct learned-knowledge count, distinct badge
count, and mission completion. Task ID and title come from the canonical
`MissionDefinition`, not from UI text.

Recent conversation is not converted into memory. The interaction topic and
milestone collections are empty because no approved business-owned source
currently exists for them.

The profile UI's derived `Lv.1` / `Lv.2`, percentages, visual counters, scores,
and other presentation-only values are excluded. There is no real user system,
so nickname, user ID, level, and score do not exist in the contract.

## Contract

`ReadOnlyCharacterContext` contains three value-only sections:

- Character: `animalId`, `unlocked`, `learnedKnowledgeCount`,
  `earnedBadgeCount`
- Task: `taskId`, `taskTitle`, `completed`
- Interaction: `recentTopics`, `recentMilestones` (empty in R3.3A)

The DTOs have no public fields or setters, no `UnityEngine.Object`, service,
callback, repository, or write method. Collection getters return defensive
copies. `Empty` is the backward-compatible value when context is unavailable.

`AnimalProgressService.TryGetSnapshot` clones an existing record and never
calls the write-producing `GetOrCreate` path. Unknown animals therefore return
empty context without creating progress.

## Request and provider flow

`AIManager` depends only on `IReadOnlyCharacterContextProvider`. It captures a
fresh snapshot for each request. Missing providers and provider exceptions fail
open for chat availability but fail closed for context: the request continues
with `ReadOnlyCharacterContext.Empty`.

The same `AIRequest` and snapshot travel through `AIRouter`. The cloud adapter
passes it through the existing `ChatApiClient`; the local adapter serializes it
in the same request shape; the deterministic Unity knowledge provider receives
the same request object. Provider selection does not change the context.

Python sanitizes the request again with a strict allowlist, bounds text/counts,
requires the context animal ID to match the requested animal, and discards all
unknown fields. Context is placed in an explicit
`<UNTRUSTED_USER_CONTEXT>` block. It cannot override system instructions, R2
canonical evidence, citations, or R3 action policy. Local and Cloud prompts use
the same sanitized context.

The server response does not echo context or expose mutation fields. Context
is request-only and is not stored in `AIResponse`.

## Grounding, actions, and history

R2 remains authoritative for scientific facts. A malicious task title in the
untrusted context cannot replace the approved canonical answer or citation.

R3 actions continue through the existing candidate, policy, capability,
validator, one-shot token, and controller chain. Read-only context does not
create candidates and cannot modify capabilities or Animator state.

The existing chat history schema remains exactly `role` and `content`. Context
is not written to history, and restoring history cannot recreate context or
trigger an action.

## TDD and automated verification

RED evidence was captured before implementation:

- Python focused tests failed because `sanitize_readonly_context` did not exist.
- Unity EditMode compilation failed because the context contract and provider
  interface did not exist.

Final GREEN regression on Unity 6000.0.76f1 ARM64:

- Python: 74/74 passed (baseline 69; five context/prompt-boundary tests added)
- Unity EditMode: 280/280 passed (baseline 269; eleven provider, routing, DTO,
  no-write, and compatibility tests added)
- Unity PlayMode: 28/28 passed
- C# compile errors: 0
- `NullReferenceException`: 0
- unhandled exceptions: 0
- `git diff --check`: passed

Coverage includes defensive snapshots, no-write behavior, unknown-animal
isolation, missing-context degradation, Local/Cloud/Unity-route consistency,
strict Python allowlisting, prompt-injection boundaries, R2 evidence priority,
request-only response behavior, and unchanged history schema.

## Known limitations and follow-up

- Recent topics and milestones remain empty until R3.3B introduces an approved,
  business-owned event source.
- No long-term character memory or summarization exists.
- Context currently informs LLM prompts but deterministic Unity fallback prose
  does not personalize its answer from context; it only receives the same
  request snapshot.
- No account/user-switching system exists, so cross-user memory isolation is a
  future concern rather than an implemented feature.
- This infrastructure change does not require a new physical-device behavior
  acceptance pass; existing R2/R3 automated regressions remain green.

R3.3A is ready for local merge review after the branch commits remain clean.
R3.3B must be separately designed and authorized before adding events or
persistent memory.
