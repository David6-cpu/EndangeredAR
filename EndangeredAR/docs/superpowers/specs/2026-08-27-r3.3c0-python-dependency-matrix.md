# R3.3C0 Python Dependency Matrix

**Scope:** Define what must move onto iPhone before EndangeredAR can claim a production on-device LLM path. This document does not authorize production router changes.

## Target Boundary

The production iOS conversation path must run without HTTP, LAN, Python, Mac-hosted llama.cpp, or Cloud:

```text
Unity Chat UI
  -> Unity intent and safety classification
  -> Unity canonical knowledge retrieval
  -> Unity current-state and character-memory snapshots
  -> Unity trusted prompt builder
  -> OnDeviceLLMProvider
  -> iOS native bridge
  -> llama.cpp + Qwen2.5-1.5B-Instruct GGUF + Metal
  -> Unity response validation
  -> existing action policy and UI
```

The existing Mac HTTP path remains a Development-only reference and benchmark. It must be named `development_remote_llm` in provenance and must not be required by an iOS Release build.

## Production Exit Rule

No capability in the production column may require a Python process, localhost or LAN endpoint, Mac file path, Cloud credential, or Development route selection. The R3.3C0 Spike proves only native model loading and completion. It does not satisfy the production exit rule until the later Unity-owned retrieval, prompt, validation, and routing work is complete.

## Security and Privacy

- The native runtime receives a filesystem path inside the installed app bundle, never model bytes copied through C#.
- The GGUF, generated Xcode project, XCFramework binary, build logs, and device metrics remain outside Git.
- No profile key, event ID, idempotency key, raw memory event, user identity, device identifier, credential, or local filesystem path enters the prompt or committed artifacts.
- Python remains useful for validation and benchmarking, but it is not part of the iOS Release trust boundary.
