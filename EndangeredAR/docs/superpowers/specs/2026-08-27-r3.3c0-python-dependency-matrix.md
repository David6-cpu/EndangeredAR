# R3.3C1 Production Chat Python Dependency Matrix

**Scope:** Define the production iOS chat ownership boundary after the R3.3C0 native Spike and track every dependency that R3.3C1 must remove from the user-facing runtime. Python remains a supported development and quality tool, but it is outside the production iOS trust and execution boundary.

## Target Boundary

```text
Unity Chat UI
  -> Unity intent, authority, and local canonical retrieval
  -> Unity current-state and character-memory snapshots
  -> Unity trusted prompt and token-budget policy
  -> iOS native chat template, tokenizer, and llama.cpp generation
  -> Unity authority-aware response validation
  -> Unity trusted metadata, action policy, and UI
```

The production chain must run with no Python process, HTTP endpoint, Mac, LAN, Cloud credential, server rule, server knowledge answer, or Unity fallback chat. The Mac llama.cpp adapter and Cloud route remain explicit Development comparison tools.

## Classification

- **A - Already Unity-owned:** The authoritative implementation already exists in Unity; R3.3C1 may compose or narrow it without moving ownership.
- **B - Must migrate to Unity:** The production behavior currently lives in Python or is incomplete in Unity and must become application-owned C#.
- **C - Native llama runtime:** The operation belongs in the pinned iOS llama.cpp bridge because it depends on the loaded model, vocabulary, chat template, or decode runtime.
- **D - Development-only Python:** Python may retain the behavior for tests, vectors, benchmark, Mac reference inference, or Cloud experiments, but Release cannot call it.
- **E - Remove from production path:** The capability may remain as isolated diagnostic code, but it must have no user-facing production authority or automatic route.

## R3.3C1 Final Production State

The real bottom Chat UI now completes the production conversation path without Python or HTTP:

1. Unity classifies intent and selects the content authority.
2. Unity retrieves canonical evidence, current Progress, or minimized character Memory.
3. Unity builds and token-budgets the trusted prompt.
4. The iOS native bridge applies the pinned GGUF chat template, tokenizes, and runs Qwen with llama.cpp and Metal.
5. Unity validates generated text, composes immutable citation and grounding metadata, authorizes actions from trusted metadata, and records exact provenance.

The Mac Python adapter, Mac llama.cpp server, Cloud provider, server rule, server knowledge reply, and Unity fixed-chat fallback remain development or diagnostic code only. None is reachable from the production iOS chat composition.

## R3.3C1 Exit Measurement

`Production Chat Python Dependencies = 0` is an exit condition, not a claim about the R3.3C0 baseline. It is satisfied only when:

- non-Development iOS composition contains only the on-device language provider;
- bottom Chat UI requests complete with Mac Python and llama-server stopped and all iPhone networking off;
- Unity performs retrieval, prompt construction, authority validation, metadata composition, and error mapping;
- native llama.cpp performs only model lifecycle, chat-template application, tokenization, and generation;
- no Release code path calls a Python URL, Cloud provider, server rule, server knowledge final reply, or Unity fallback chat.

R3.3C1 satisfied this exit measurement on 2026-08-27. The physical-device gate ran the real bottom Chat UI with the Mac adapter and llama-server stopped and iPhone networking disabled. Seven authority scenarios completed through `on_device_llm`; the grounded diet scenario retained trusted citations and played Eat once before returning to Idle.

## Security and Privacy

- No profile key, event ID, idempotency key, raw Memory event, user identity, device identifier, credential, local filesystem path, or model path enters the prompt or provenance.
- The provider receives copied trusted messages and generation parameters, not Service, Unity Object, Progress, Memory store, or knowledge repository references.
- The GGUF, XCFramework, generated Xcode project, test output, device logs, signing data, runtime Memory, and runtime Progress stay outside Git.
- Python remains valuable for corpus validation, shared vectors, reference inference, benchmarking, and Cloud experiments, but it is not installed, invoked, or reachable inside the production iOS conversation path.
