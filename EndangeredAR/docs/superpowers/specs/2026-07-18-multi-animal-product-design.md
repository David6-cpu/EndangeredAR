# 濒危动物交互科普系统：多动物产品化设计

日期：2026-07-18

## 1. 背景与目标

当前 Unity 工程已经能够完成森森的相机识别、3D 模型展示、手势旋转缩放、AI 对话、轻量任务、学习内容和科普卡片流程。下一阶段不再以单角色比赛 Demo 为目标，而是建设可持续扩展的多动物科普产品。

首个多动物版本支持三只动物：

- 缨冠灰叶猴“森森”
- 大熊猫
- 雪豹

首版目标是证明系统能够通过配置新增动物，而不是复制场景、页面和业务判断。新增第四只动物时，应主要增加动物配置、模型、知识和任务资源，不修改通用页面流程。

## 2. 已确认的产品决策

- 底部导航使用“图鉴 / 中央扫描 / 我的”三栏结构。
- 首次扫描对应识别卡后解锁动物图鉴。
- 动物解锁后，用户可以从图鉴直接进入该动物的 3D 互动页，不再重复扫描。
- 点击已解锁动物后直接进入 3D 互动，不经过额外档案首页。
- 首版解锁状态、学习进度、徽章和最近对话保存在设备本地。
- 三只动物的模型、纹理、知识和任务配置全部随 App 安装。
- AI 使用审核知识档案、服务端角色 Prompt、后端 LLM 和客户端本地 fallback。
- 每只动物拥有一个 30 至 60 秒的专属轻量任务，共用同一任务框架。
- 扫描采用相机识别卡片后切换到独立 3D 页面，不恢复 AR Foundation 图片追踪，也不宣称模型具备真实空间锚定能力。
- 大熊猫和雪豹正式模型尚未准备；多动物架构阶段先使用明确标记的临时模型，后续通过配置替换为有授权的 GLB。

## 3. 产品范围

### 3.1 首版包含

- 三动物图鉴及锁定、解锁状态。
- 三张识别卡与 `animalId` 映射。
- 首次扫描解锁与重复扫描直接进入互动。
- 统一 3D 互动页。
- 按动物隔离的 AI 角色、知识和最近对话。
- 三个专属轻量任务。
- 按动物生成的学习记录、徽章和科普卡片。
- 本地进度持久化与版本迁移基础。
- 网络、模型和存档失败的 fallback。

### 3.2 首版不包含

- AR Foundation 或真实空间模型锚定。
- 账号登录和云端进度同步。
- 在线下载动物模型或内容包。
- 多人互动、排行榜和社区。
- 内容管理后台和运营数据平台。
- 三只动物之外的正式内容。

## 4. 用户流程

### 4.1 首次发现

1. 用户点击中央扫描按钮。
2. App 打开相机并识别动物卡片。
3. 识别器输出对应 `animalId`。
4. 系统校验动物配置并执行解锁。
5. 本地保存解锁时间和初始学习进度。
6. 显示动物名称、欢迎语和解锁反馈。
7. 进入统一 3D 互动页。

识别失败时继续扫描或返回图鉴，不写入解锁状态。

### 4.2 后续重访

1. App 启动时读取本地进度。
2. 图鉴展示三只动物及其锁定状态。
3. 用户点击已解锁动物。
4. 系统恢复该动物的最近对话、任务、徽章和学习进度。
5. 直接进入统一 3D 互动页。

锁定动物卡片只展示发现提示，不允许绕过扫描进入互动。

## 5. 系统架构

### 5.1 AnimalDefinition

使用 Unity `ScriptableObject` 描述动物身份和展示资源：

- `animalId`
- 中文名、学名、简介
- 图鉴头像和锁定剪影
- 识别卡与识别参数
- GLB 相对路径、基础缩放、旋转和展示偏移
- 欢迎语和主题色
- 知识配置引用
- 任务配置引用
- 科普卡片主题资源

所有系统通过 `animalId` 查询配置，不直接判断森森、大熊猫或雪豹名称。

### 5.2 AnimalKnowledgeProfile

每只动物拥有一份审核过的本地知识档案：

- 栖息地
- 食物
- 濒危等级与原因
- 生存威胁
- 保护措施
- 今日知识列表
- 角色化欢迎语
- 常见问题与本地 fallback 回答

客户端档案用于页面展示和断网回答。服务端维护同版本的角色 Prompt 与审核知识，用于约束 LLM。

### 5.3 MissionDefinition

任务使用统一数据结构：

- 任务 ID、名称和说明
- 选项列表
- 正确答案或判定规则
- 正确、错误反馈
- 奖励知识 ID
- 徽章 ID 和积分

首版任务：

- 森森：寻找适合的森林食物。
- 大熊猫：选择健康竹林或修复竹林。
- 雪豹：识别栖息地威胁与保护迁徙通道。

### 5.4 运行模块

- `AnimalCatalogService`：加载动物配置并向图鉴提供查询接口。
- `AnimalProgressRepository`：读取、迁移、保存本地进度。
- `ScanUnlockController`：相机识别、`animalId` 映射和首次解锁。
- `AnimalExperienceController`：切换当前动物、加载模型、管理展示与手势。
- `AnimalChatController`：维护当前动物会话、调用后端并处理本地 fallback。
- `MissionController`：根据当前 `MissionDefinition` 执行任务状态机。
- `KnowledgeCardController`：根据当前动物和学习进度生成卡片。
- `AppNavigationController`：只负责图鉴、扫描、我的和互动页之间的导航。

现有 `DemoAppController` 采用渐进迁移，不进行一次性重写。迁移完成后，它只保留导航协调职责或被 `AppNavigationController` 替代。

## 6. 本地进度设计

本地 JSON 使用带版本号的数据结构：

```text
schemaVersion
animals[]
  animalId
  unlocked
  unlockedAt
  learnedKnowledgeIds[]
  missionCompleted
  earnedBadgeIds[]
  recentConversation[]
```

规则：

- 每只动物状态独立保存。
- 每只动物最多保留最近 10 轮对话。
- 保存时先写临时文件，成功后替换正式文件。
- 读取失败时保留损坏文件副本并恢复默认进度。
- 未知 `animalId` 数据保留但不展示，避免版本降级造成永久丢失。
- `schemaVersion` 负责字段迁移，为以后账号同步预留空间。

## 7. AI 数据流

Unity 客户端向后端发送：

```text
animalId
message
recentHistory
```

后端根据 `animalId` 选择服务端角色 Prompt 和审核知识，再调用 LLM。API Key 仅存在于服务端，不写入 Unity 配置、日志或安装包。

回复要求：

- 保持当前动物身份，不串角色。
- 面向青少年，简短、自然、角色化。
- 优先使用审核知识，不确定时明确表达不知道。
- 拒绝危险、违法或不适龄内容。
- 自然加入生态保护引导，不进行生硬说教。

网络失败、超时或后端拒绝请求时，客户端按当前 `animalId` 使用本地知识回答，并保持主流程可继续。

## 8. 页面与组件结构

### 8.1 动物图鉴

- 默认首页。
- 展示三只动物的解锁状态、头像、进度和最近互动。
- 点击已解锁动物进入统一 3D 互动页。
- 点击锁定动物显示对应扫描提示。

### 8.2 扫描发现

- 相机预览保持原始比例，不拉伸。
- 识别框、提示和手动返回位于 Safe Area 内。
- 页面只处理识别与解锁，不承载聊天和任务。

### 8.3 3D 互动

- 根据当前动物配置加载模型和展示参数。
- 支持旋转和双指缩放。
- 包含角色聊天气泡和底部输入框。
- 知识档案、专属任务和科普卡片作为页内抽屉或弹层打开。
- 不显示底部主导航，使用顶部返回按钮，避免与聊天输入区域冲突。

### 8.4 我的

- 汇总生态守护等级。
- 展示图鉴完成度、跨动物徽章、学习统计和今日保护行动。
- 不包含开发测试路径、调试按钮或本地文件信息。

同一时刻只允许一个主页面处于激活状态。弹层关闭后返回同一动物的互动状态，不能重置模型、对话或任务进度。

## 9. 错误处理

- 缺少动物配置：跳过该动物并记录清晰错误，不阻止 App 启动。
- 识别到未知卡片：继续扫描，不写入解锁状态。
- 模型文件缺失或加载失败：显示动物头像、错误提示和重试入口，知识与聊天仍可使用。
- 网络失败：使用当前动物本地 fallback，不展示原始异常信息。
- 存档损坏：备份损坏文件，恢复默认存档，并向用户显示非技术性提示。
- 重复扫描已解锁动物：不重复发放奖励，直接恢复该动物互动状态。
- 应用中断：页面恢复后不重复提交任务或聊天请求。

## 10. 迁移与交付顺序

### 阶段 0：建立稳定基线

- 添加标准 Unity `.gitignore`。
- 提交当前可运行森森版本并创建稳定标签。
- 记录现有 Demo 的启动、扫描、模型、聊天、任务和卡片烟雾测试结果。

### 阶段 1：迁移森森

- 建立动物、知识、任务和进度数据结构。
- 将森森迁移为配置驱动。
- 保持森森现有完整流程和 UI 行为。
- 拆出目录、进度、体验、聊天和导航职责。

### 阶段 2：三动物图鉴与统一互动

- 建立“图鉴 / 扫描 / 我的”导航。
- 实现动物锁定与解锁状态。
- 使用临时模型接入大熊猫和雪豹。
- 验证三个 `animalId` 可独立加载模型、对话、知识和任务。

### 阶段 3：内容与扫描解锁

- 加入三份审核知识档案。
- 加入三套角色 Prompt 和本地 fallback。
- 加入三项专属任务及徽章。
- 完成三张识别卡映射、首次解锁和重复扫描逻辑。

### 阶段 4：正式模型与发布验证

- 将有授权的大熊猫和雪豹 GLB 替换到配置中。
- 优化模型缩放、偏移、材质和性能。
- 完成 iPhone 真机、Safe Area、相机方向、断网、存档损坏和低内存验证。
- 固化录屏流程和正式产品文案。

## 11. 测试与验收

### 11.1 EditMode 测试

- 根据 `animalId` 查询正确配置。
- 未知动物不会导致空引用崩溃。
- 解锁状态可以保存并恢复。
- 存档版本迁移结果正确。
- 三项任务的正确、错误判定与奖励正确。
- 聊天请求只包含当前动物 ID 和对应历史。

### 11.2 PlayMode 测试

- 图鉴、扫描、我的三个主页面互斥显示。
- 三张识别卡分别解锁正确动物。
- 重复扫描不会重复奖励。
- 重启后图鉴状态保持。
- 三只动物都能进入统一互动页。
- 切换动物后模型、知识、任务和对话不会串数据。
- 网络失败时聊天切换本地回答。
- 模型失败时仍可进入知识和聊天。

### 11.3 真机验收

- iPhone 17 Pro Max 竖屏无重叠、裁切或 Safe Area 侵入。
- 相机画面方向正确且比例不拉伸。
- 底部导航和聊天输入框始终可点击。
- 三个随包模型加载期间不导致明显卡死。
- 连续切换三只动物后内存保持稳定。
- Console 和 Xcode 运行日志无未处理异常。

## 12. 风险与控制

- `DemoAppController` 过大：采用逐模块迁移，每个阶段保持可运行，不进行大爆炸式重写。
- 正式模型缺失：临时模型只用于架构验证，不用于最终宣传素材；正式资源必须记录授权来源。
- 科普内容错误：所有上线知识必须经过人工审核，LLM 不能作为事实源。
- 包冲突复发：首版不恢复 AR Foundation，不新增非必要 Unity 包。
- 资源体积增加：三只动物随包交付，导入时限制纹理尺寸、网格复杂度和动画数量；资源下载留到后续版本。
- 本地进度无法跨设备：首版明确为设备本地存储，数据结构预留未来云同步字段。

## 13. 完成定义

首个多动物版本完成时，用户可以在一台 iPhone 上：

1. 分别扫描森森、大熊猫和雪豹识别卡。
2. 首次扫描后永久解锁对应动物图鉴。
3. 从图鉴直接进入任意已解锁动物的 3D 互动页。
4. 与三只动物进行角色一致的 AI 对话，并在断网时获得本地回答。
5. 完成每只动物的专属任务并获得独立学习记录和徽章。
6. 关闭并重新打开 App 后保留解锁与学习进度。

新增第四只动物时，不复制场景和页面，不修改通用导航与互动逻辑，只增加配置、模型、知识、任务和识别卡资源。
