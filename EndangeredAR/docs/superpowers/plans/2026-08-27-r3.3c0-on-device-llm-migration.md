# R3.3C0 iPhone On-Device LLM Migration Gate Implementation Plan

> **Execution rule:** Complete this Spike before resuming R3.3C physical-device A-H. Do not merge, push, change the production AI router, or claim production on-device inference from Editor or Mac-hosted results.

**Goal:** Prove that the current Qwen2.5-1.5B-Instruct Q4_K_M GGUF can load and generate a real completion inside the EndangeredAR iOS app through llama.cpp and Metal while Mac services and all iPhone networking are off.

**Architecture:** A Development-only Unity panel invokes an asynchronous C# polling adapter. The adapter calls a narrow C ABI implemented by an Objective-C++ iOS plugin linked to a pinned llama.cpp XCFramework. The model is validated and temporarily staged into the iOS app bundle at build time, loaded directly by filesystem path, and never committed or copied into managed memory. This Spike is isolated from `AIManager`, R2, Memory, Progress, and actions.

**Pinned dependencies:**

- llama.cpp tag `b10643`, commit `192067b72d1b7a3653b3f0c59190303b18596637`.
- Official iOS device build: arm64, Metal enabled, embedded Metal library, minimum iOS 16.4.
- llama.cpp license: MIT.
- Model: Qwen2.5-1.5B-Instruct Q4_K_M GGUF, exact filename `qwen2.5-1.5b-instruct-q4_k_m.gguf`, size `1117320736`, SHA-256 `6a1a2eb6d15622bf3c96857206351ba97e1af16c30d7a74ee38970e434e9407e`.
- Qwen2.5-1.5B-Instruct license: Apache-2.0.

## Global Constraints

- The GGUF and XCFramework are external build inputs and must remain untracked.
- Use `ENDANGERED_AR_MODEL_PATH` and `ENDANGERED_AR_LLAMA_XCFRAMEWORK_PATH`; never persist their values.
- Model staging must use a temporary `StreamingAssets/OnDeviceModels` location, validate identity before copying, and remove the staged model plus generated metadata in `finally`.
- Load the GGUF from the installed app bundle path. Do not use `Resources.Load`, `TextAsset`, `byte[]`, or a second persistent copy.
- Do not expose C++ types to C#. All native strings use UTF-8 caller buffers, and all native objects remain native-owned.
- Use one serial native worker and one active generation. Unity polls status; native code never reverse-calls managed code from a worker thread.
- Cancellation is cooperative between decode steps. A cancelled or failed context is not reused until it returns to a known ready state or is reloaded.
- The fixed Spike prompt is `用一句中文介绍你自己。`; the Development UI accepts no arbitrary prompt.
- Provenance `on_device_llm` is set only after a native completion. Editor stubs and Mac HTTP completions cannot set it.
- The Spike uses iOS 16.4 without silently changing the long-term product deployment target.
- Test output, generated Xcode projects, signing data, model weights, frameworks, and device logs remain outside the repository.

## Spike Exit Criteria

R3.3C0 passes only when all are true:

1. The XCFramework is built from the pinned official commit for iOS device arm64 with Metal.
2. The approved GGUF passes exact filename, size, and SHA-256 validation and loads directly from the app bundle.
3. Mac Python and Mac llama-server are stopped.
4. iPhone Wi-Fi and cellular data are off.
5. The fixed prompt produces a real native llama.cpp completion.
6. Provenance reports `on_device_llm` and cannot be produced by an Editor stub or remote provider.
7. UI/AR remains responsive, background cancellation and foreground recovery work, and the app has no crash or jetsam.
8. Performance and thermal metrics are recorded from the real EndangeredAR scene.
9. No GGUF, XCFramework, generated Xcode project, build output, credential, signing material, device log, or local path is committed.
10. Python, EditMode, and PlayMode regressions pass.

Only after this gate may R3.3C resume with a separate plan to migrate Unity prompt construction, production `OnDeviceLLMProvider`, local R2 composition, response validation, Memory/current-context integration, and final airplane-mode A-H acceptance.
