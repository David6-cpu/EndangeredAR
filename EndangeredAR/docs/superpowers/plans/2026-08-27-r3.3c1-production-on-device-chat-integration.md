# R3.3C1 Production On-Device Chat Integration Implementation Plan

> **Execution rule:** Connect the real bottom Chat UI to iPhone on-device Qwen without Python, HTTP, LAN, Cloud, or Unity fallback chat in the production route. Keep R3.3C Final A-H paused until the six-question offline Chat UI gate passes. Do not merge, push, or start R3.4.

**Goal:** Replace the Mac-hosted development language path with an iOS production composition in which Unity owns intent, authority, evidence, current state, character Memory, prompt construction, response validation, trusted metadata, and actions, while the native llama.cpp runtime only applies the model chat template, tokenizes, and generates bounded text.

**Production architecture:**

```text
DemoAppController bottom Chat UI
  -> ChatRequestState ticket
  -> AIManager production composition
  -> Unity MemoryMentionPolicy + ContentAuthorityResolver
  -> Unity CanonicalKnowledgeRetriever
  -> R3.3A ReadOnlyCharacterContext
  -> R3.3B/C ReadOnlyCharacterMemoryContext
  -> TrustedChatPromptBuilder + OnDevicePromptBudget
  -> OnDeviceLLMProvider
  -> iOS native llama.cpp + Qwen chat template + tokenizer + Metal
  -> AuthorityAwareResponseValidator
  -> Unity-owned AIResponse metadata
  -> existing ActionPolicy + Capability + AIInteractionValidator
  -> reply, citations, history, and optional validated action
```

**Pinned runtime and model:**

- llama.cpp tag `b10643`, commit `192067b72d1b7a3653b3f0c59190303b18596637`.
- iOS device arm64 XCFramework, Metal enabled, minimum iOS 16.4.
- Qwen2.5-1.5B-Instruct Q4_K_M, filename `qwen2.5-1.5b-instruct-q4_k_m.gguf`.
- Model size `1117320736` bytes and SHA-256 `6a1a2eb6d15622bf3c96857206351ba97e1af16c30d7a74ee38970e434e9407e`.
- The GGUF and XCFramework remain external build inputs and never enter Git.

## Current Data Flow Audit

The current bottom Chat UI calls `DemoAppController.AskLocal`, creates a `ChatRequestTicket`, snapshots `role/content` history in `BuildAIRequest`, and invokes `AIManager.Send`. `AIManager` creates R3.3A current-state and R3.3C Memory snapshots, classifies Memory mention mode and content authority, then constructs `LocalLLMProvider`. Despite its name, that provider posts to Python `/chat/local`; Python performs canonical retrieval, prompt construction, llama-server generation, response validation, and response metadata assembly. `DemoAppController` performs ticket, animal, page, Capability, Controller, and action validation before displaying the reply and saving successful assistant text.

The iOS Spike is deliberately separate. `OnDeviceLLMSpikePanel` calls `OnDeviceLLMSpikeRunner`, which polls `OnDeviceLLMNativeBackend`. The native bridge loads one GGUF into a retained model/context, applies the GGUF chat template to a fixed system/user pair, clears llama memory before generation, and runs asynchronously on a serial queue. It does not accept structured messages, does not expose tokenizer counts, and is not connected to `AIManager`.

Unity already has a local R2-compatible data path: `content/animals/sensen.json` is the canonical source, `AnimalContentAssetBuilder` creates `SensenKnowledge.asset`, `AnimalKnowledgeProfile.Retrieve` deterministically selects entries, and canonical sources are retained in the generated asset. The remaining production defect is that `LocalKnowledgeChatService` and `LocalKnowledgeProvider` still treat `approvedAnswer` or fixed templates as final user replies. R3.3C1 will use the profile as an authority source and produce an evidence package instead.

## Production Trust Boundary

- Progress is the only current business-state authority.
- `CharacterMemoryProjection` is the only long-term Memory authority.
- The generated `AnimalKnowledgeProfile` is the production canonical knowledge artifact and must remain reproducible from repository canonical JSON.
- `GroundingTopic`, grounded fact IDs, evidence status, citations, content authority, and action candidates are fixed by Unity before generation.
- The native provider accepts only already-built messages, generation parameters, and a generation identity. It returns only text, metrics, and a bounded error.
- Native KV state is cleared before every independent request. Unity history is the only session history.
- Model text cannot create or alter citation identity, Memory, Progress, Taunt, Eat, Capability, Policy, Validator, or Animator state.
- A failed or invalid native reply becomes `system_status`; it never falls back to fixed character language, Python, development remote, Cloud, server rule, or server knowledge.

## Exit Criteria

R3.3C1 passes only when all are true:

1. Production Chat Python dependency count is zero.
2. The real bottom Chat UI uses `OnDeviceLLMProvider` and native Qwen on iPhone.
3. Native chat template and tokenizer are used without C# special-token literals.
4. Token budget preserves system, current user, and authority facts and drops oldest history deterministically.
5. Unity local R2 matches shared Python reference vectors for classification and fact IDs.
6. Citations, grounding topic, grounded fact IDs, evidence status, and actions remain Unity-owned.
7. Current Progress and Character Memory are read-only prompt authorities and cannot be modified by model output.
8. Memory Clear, animal switch, page switch, cancellation, and stale completion cannot display or save obsolete claims.
9. Authority validation and one strict on-device repair attempt fail closed to system status.
10. Diet evidence still authorizes one Eat through Policy/Capability/Validator, Taunt remains deterministic, and model text alone authorizes neither.
11. Release composition has no automatic Development remote, Cloud, Unity fallback, server rule, or server knowledge response path.
12. The model loads once, each request clears hidden KV state, and only one generation runs at a time.
13. The approved GGUF appears exactly once in the installed bundle and remains untracked.
14. A non-Development iOS build links the approved arm64 framework and does not require AI-related LAN or HTTP exceptions.
15. With Mac Python and llama-server stopped and iPhone Wi-Fi/cellular off, the six bottom-Chat scenarios succeed with `languageGenerator=on_device_llm` and `finalSource=on_device_llm`.
16. Performance, memory, thermal, responsiveness, background, crash, and jetsam evidence is recorded from the real EndangeredAR scene.
17. Python, EditMode, and PlayMode suites meet or exceed 129/473/38 and all added tests pass.
18. Security scans, `git diff --check`, and the worktree are clean after commits.

Only after this gate may the full R3.3C A-H acceptance resume. R3.3C1 does not authorize merge, push, R3.4, model replacement, Memory schema changes, new events, new actions, Cloud fallback, or Python removal from the development toolchain.
