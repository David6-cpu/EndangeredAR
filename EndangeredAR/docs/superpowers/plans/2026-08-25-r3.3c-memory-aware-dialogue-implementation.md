# R3.3C Memory-aware Dialogue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let dialogue read bounded, application-owned character milestone memory in explicitly allowed situations without changing Progress, Memory persistence, grounded knowledge, or action authority.

**Architecture:** `CharacterMemoryProjection` is converted on every request into an immutable, de-identified `ReadOnlyCharacterMemoryContext`. A deterministic mention policy either resolves explicit recall locally or conditionally supplies a reunion-only context to Local/Cloud providers; every factual memory sentence remains application-owned, while existing completion tickets and a snapshot fingerprint prevent stale claims after clear, reload, or animal changes.

**Tech Stack:** Unity 6000.0.76f1 ARM64, C#, Unity `JsonUtility`, Python 3 `unittest`, NUnit EditMode/PlayMode tests, Local/Cloud HTTP providers, deterministic Unity Knowledge fallback.

**Spec:** Approved R3.3C implementation authorization in the current task. Prerequisites are `EndangeredAR/docs/verification/2026-08-25-r3.3b-event-memory-acceptance.md` and the existing R3.3A read-only context implementation.

## Global Constraints

- Progress remains the only source of current business truth; `CharacterMemoryProjection` remains the only source of long-term milestone memory.
- Do not change Memory document/event/repository schemas, idempotency, bootstrap, reconcile, clear/suppression, Progress transitions, R2 knowledge, Animator assets, Action Policy, Capability, or Validator.
- Do not expose `profileKey`, `eventId`, `idempotencyKey`, raw `subjectId`, `occurredAtUtc`, event origin, file paths, device data, user identity, prompts, or chat text in Memory context.
- Memory never writes business state, creates an action candidate, changes grounding metadata, or grants `memory_recall` through a network response.
- R2 canonical evidence outranks R3.3A current state; current state outranks R3.3B memory; Memory outranks session history only for explicit historical claims.
- Explicit recall and conversation-history-boundary facts are deterministic. Reunion facts are deterministic; a provider may return only a bounded, non-factual greeting tail.
- Every Memory-dependent completion revalidates ticket generation, animal ID, current Store status, mention mode, and the current context fingerprint before display or history persistence.
- Every task follows RED, verifies the intended failure, applies minimal GREEN, runs focused tests, runs full Python/EditMode/PlayMode regression, and creates one coherent commit.
- Test artifacts remain outside the repository. No runtime Memory/Progress files, device logs, exports, credentials, signing material, or local absolute paths are committed.

## Locked Contracts

```csharp
public enum CharacterMemoryContextStatus
{
    Unavailable,
    Empty,
    Available
}

public enum CharacterMemoryContextMilestoneKind
{
    AnimalDiscovered,
    MissionCompleted,
    KnowledgeLearned,
    BadgeEarned
}

public enum MemoryMentionMode
{
    None,
    ExplicitRecall,
    ConversationHistoryBoundary,
    Reunion
}

public sealed class ReadOnlyCharacterMemoryContext
{
    public int SchemaVersion { get; }
    public string AnimalId { get; }
    public CharacterMemoryContextStatus Status { get; }
    public bool Discovered { get; }
    public int CompletedMissionCount { get; }
    public int LearnedKnowledgeCount { get; }
    public int EarnedBadgeCount { get; }
    public IReadOnlyList<ReadOnlyCharacterMemoryMilestone> Milestones { get; }
    internal string Fingerprint { get; }
}

public sealed class ReadOnlyCharacterMemoryMilestone
{
    public CharacterMemoryContextMilestoneKind Kind { get; }
    public string DisplayLabel { get; }
}

public interface IReadOnlyCharacterMemoryContextProvider
{
    ReadOnlyCharacterMemoryContext CreateSnapshot(
        string animalId,
        ReadOnlyCharacterContext currentContext);
}
```

Wire values are exact lowercase strings: statuses `unavailable`, `empty`, `available`; use modes `none`, `reunion`; milestone kinds `animal_discovered`, `mission_completed`, `knowledge_learned`, `badge_earned`. Explicit recall and history-boundary modes remain application-internal and are never accepted from the network.
